## 1. 總覽

- **風格**：奧斯曼式（Haussmann）巴黎公寓。石材立面；二樓與頂樓有連續陽台；屋頂是鋅板孟莎屋頂。
- **產物**：
  - `public/assets/kit.glb`：零件模型，第一版全部完成時約 82 個
  - `public/assets/kit_manifest.json`：零件清單
  - `public/assets/tex/`：自製貼圖
- **分工**：kit 只放「重複出現、形狀固定」的零件。長度會隨建築變化的幾何由網頁端產生，包括屋頂平台、盲牆、室內房間盒、窗簾。

## 2. 座標與單位

- 單位是公尺。Blender 的 Z 軸朝上；匯出時保持 Z-up，網頁端把根節點繞 X 軸轉 −90°（和參考站、v1 相同）。
- **立面零件的局部座標**：
  - 外牆面在 y = 0。**外側是 −Y**，往內是 +Y。
  - 從外面看，+X 向右。
  - 原點在開間底部的中心：x = 0 是開間中線，z = 0 是該樓層的樓板面。
  - 牆厚 0.4 m（y 從 0 到 0.4）。線腳、陽台往 −Y 凸出。
- **轉角零件**的原點在兩個立面外牆面的交點。零件佔據 x ≥ 0、y ≥ 0 的轉角方格（和參考站相同）。
- 每個立面擁有自己**左端**（從外面看）的轉角。從上方看，四個立面逆時針排列：正面 → 右側 → 背面 → 左側。

## 3. 網格與尺寸

### 3.1 水平

| 項目 | 尺寸 | 說明 |
|---|---|---|
| 開間 | 3.0 m | 每個開間一扇窗 |
| 直角轉角 | 1.0 × 1.0 m | 轉角柱 |
| 斜切轉角 | 4.0 × 4.0 m 方格 | 斜面寬 4.24 m，兩側返回段各 1.0 m |
| 連棟端柱 | 0.5 m | 立面接到鄰棟的那一端 |

- 立面長度 = 左端轉角寬 + 3 × 開間數 + 右端轉角寬。獨棟固定是 3n + 2（和參考站相同）。
- **斜切轉角會吃掉兩側立面各一個開間**。兩端都斜切的立面，一般開間只剩 n − 2 個。這樣不論轉角類型，平面都維持 3n + 2。
- 斜面中間 3 m 放**標準開間零件**（旋轉 45°），所以窗、店面、大門、窗楣、百葉、室內都能直接沿用。兩側剩下的 0.62 m 和返回段由斜切轉角零件補上。

```
直角轉角（1 × 1 m）                斜切轉角（4 × 4 m 方格）

 y                                  y
 │ 立面 B                           │ 立面 B
 │                                4 ┤ ← B 的開間從這裡開始
 1 ┼──┐ ← B 的開間從這裡開始          │ 返回段 1.0 m
   │▓▓│                           3 ┤╲
 0 ┼──┴────── 立面 A                │  ╲  斜面 4.24 m：中間 3 m 放標準開間，
   0  1 ← A 的開間從這裡開始           │    ╲ 兩側各 0.62 m 由轉角零件補
                                  0 ┼──────┬──┬─── 立面 A
                                    0      3  4 ← A 的開間從這裡開始
```

## 4. 零件清單

## 5. 建模規範（build_kit.py）

- **全部由腳本產生**：`build_kit.py` 每次從空檔案建出 `european_kit.blend`。要改零件就改腳本或 `kit_dims.json`，不要手改 .blend，否則下次重建就會被覆蓋。
- **共用剖面函式**：腰線、簷口、陽台底板、窗套都用同一組剖面函式沿路徑擠出，相鄰零件的剖面才會完全對齊。轉角處用斜接。
- **開口不用 Boolean**：牆面直接用窗間壁、窗下、窗上的矩形拼成。拱形開口改用 2D 曲線（外框加開口形狀）填滿後轉成網格。
- **看不到的面可省略**：建築內側、牆背面、開間之間互相接觸的端面都不做。會露出來的端面才封口，例如門洞旁的勒腳、窗前欄杆的扶手、之後連棟端段零件的線腳剖面。
- **零件不超出自己的範圍**：開間零件在 x 方向剛好是 ±1.5，陽台立柱這類小構件也不能跨出邊界，否則相鄰零件會重疊閃爍。尺寸檢查會擋下超出的零件。
- **法線**：建築面用平面著色，曲面線腳用 30° 角度平滑。匯出時帶分割法線。
- **材質槽只放用到的**。
- **UV**：第 6.3 節。UV1 從階段 A 起每個零件都要產生，之後烘焙 AO 時不用重做零件。
- **尺寸檢查**：每個零件建好後，檢查外框是否符合規格。不符合就讓腳本報錯中止。
- **預覽圖**：`preview_kit.py` 把全部零件排成兩列、加上名稱，算一張 `blender/kit_preview.jpg`，方便一次檢查。
- **參考件比對**：`build_kit.py --ref` 會用「連結」（link）方式把 FrenchBuilding 的零件載入一個隱藏集合 `_REF`，只用來並排比對，不匯出。

## 6. 材質與貼圖

### 6.1 原則

每個材質由三層組成：

1. **質感層**：用世界座標的三平面投影，取樣自製的無縫貼圖組（顏色、粗糙度、高度轉凹凸）。同一個零件重複放置時，每個看起來都不一樣，相鄰零件之間也不會有接縫。
2. **圖案層**：用 UV0（公尺）在著色器裡程序化畫出需要對齊的圖案，例如石材分縫、鋅板立縫、遮雨棚條紋。
3. **AO 層**：用 UV1 取樣烘焙好的 AO 圖集（階段 F 前一律當作 1）。

### 6.2 材質清單

| 材質名 | 用在 | 質感層 | 圖案層 | 可上色 |
|---|---|---|---|---|
| `stone` | 上層牆面 | stone | 分縫（窗洞半寬 0.65） | ✓ |
| `stone_ground` | 一樓牆面 | stone | 垂直縫（窗洞半寬 0.9）；橫向溝槽用幾何做 | ✓ |
| `stone_trim` | 線腳、窗套、山花、托架、簷口、陽台底板 | stone（較細、較亮） | 無 | ✓ |
| `plaster` | 盲牆、煙囪、內院立面 | plaster | 盲牆上的煙道痕跡（階段 E） | |
| `zinc` | 陡坡、老虎窗側板、屋脊、屋頂平台 | zinc（用 UV0 而非三平面，每個實例隨機偏移） | 立縫，每 0.5 m 一條 | |
| `iron` | 扶手、欄杆框、屋脊花飾、遮雨棚架 | metal | 無 | |
| `iron_lace` | 欄杆的鐵花面板 | — | 透明鏤空貼圖（alpha cutout） | |

### 6.3 UV 規範

- **UV0（公尺）**：
  - 立面朝外的面：u = 局部 x，v = 局部 z。
  - 窗洞側壁：u = 深度，v = z。
  - 水平面：u = x，v = y。
  - 長條構件（窗框、線腳）：u 沿長向。
- **UV1（0–1）**：每個零件各自展開，不重疊，集中打包進全 kit 共用的 AO 圖集。

### 6.4 石材分縫

| 皮（從樓板面往上每 0.4 m 一皮） | 垂直縫位置（開間座標 u，每 3 m 循環） |
|---|---|
| 偶數皮 | u = 0、±1.5（開間中線與開間邊界） |
| 奇數皮 | u = ±窗洞半寬（上層 ±0.65，一樓 ±0.9） |

- 這樣排的結果：窗間壁的石塊長短交錯，窗下、窗上石塊的縫對齊窗邊。
- 轉角柱用 UV0 偏移，做出長短交錯的轉角石（harpe）。
- 分縫只畫在 `stone`、`stone_ground`；線腳和雕飾用 `stone_trim`，不畫分縫。

### 6.5 自製貼圖

| 檔案 | 內容 | 解析度 | 階段 |
|---|---|---|---|
| `tex/{組}_color.jpg` | 顏色（sRGB） | 1024² | B |
| `tex/{組}_rh.png` | R = 粗糙度、G = 高度 | 512² | B |
| `tex/iron_lace.png` | 4 種鐵花圖樣（RGBA，alpha 是鏤空） | 1024² | B |
| `tex/kit_ao.png` | 全 kit 的 AO 圖集（UV1） | 2048² | F |
| `tex/interiors.jpg` | 室內圖集 | 2048² | F |

- 貼圖組共 7 組：stone、plaster、zinc、metal、wood、terracotta、fabric。
- **做法**：在 Blender 用程序化節點做材質，由 `bake.py` 烘焙到 1 × 1 的平面上（`npm run tex`）。節點材質會一起存進 `blender/textures.blend`，可以打開來調整，但它是產物，不進 git；要改貼圖就改 `bake.py` 的配方函式。
- **無縫技巧**：把平面座標 (u, v) 映射到 4D 環面再餵給 Noise／Voronoi 節點：向量 = (cos 2πu, sin 2πu, cos 2πv)、W = sin 2πv。這樣產生的雜訊本身就上下左右循環，不需要事後修接縫，多層細節（octaves）也一樣循環。
- **鐵花圖樣**：在 Blender 用曲線畫，以正交攝影機算成透明貼圖。4 種圖樣：欄杆與圓環、交織圓環、渦卷、菱形。每格 0.9 × 0.9 m，水平方向循環；面板的 UV0 是 u = 公尺、v = 0..1（底到頂）。
- **一格貼圖對應的實際尺寸**：石材 2 m（線腳 1.25 m）、灰泥 2 m、鋅板 1.5 m、鐵件 0.5 m、木作 0.8 m、陶土 0.5 m、帆布 0.2 m。

### 6.6 每棟建築的配色

`kit.ts` 只在「可上色」材質的 InstancedMesh 上設定每個實例的顏色（instanceColor）。排列程式替每棟建築挑一組配色：

- 石材色調：微幅變化。
- 漆色：大門、店面，例如深綠、酒紅、深藍、黑。
- 百葉漆色：多半是淺灰或米灰。
- 遮雨棚顏色。

同一個零件放在不同建築上，就會有不同顏色，之後做整個街區時很有用。

### 8.4 各位置的規則

| 位置 | 規則 |
|---|---|
| 一樓 | 正面中間的一般開間放大門（偶數開間時放在中線左或右一格，依隨機種子）。其他開間依「一樓用途」放店面或窗（拱窗或方窗）；相鄰的店面開間用同一款，看起來是同一家店。側面、背面放窗；內院放方窗 |
| 斜切轉角的斜面（一樓） | 有店面時放咖啡館，否則放大門或拱窗 |
| 連續陽台 | N 列與 A 列的街道立面：每個開間放 `continuous`，每個轉角放 `corner`（斜切轉角放 `pc`，連棟端點放 `end`） |
| N 列 | 街道立面放連續陽台，每開間 2 個托架（x = ±1.1）。窗套用 `crossette`，窗楣依山花樣式 |
| A 列 | 街道立面放連續陽台，窗套用 `band`，不放窗楣 |
| 其他 S 列 | 陽台依「其他樓層陽台」。窗套用 `band`，窗楣用 `cornice`。**緊接在連續陽台下方的那一列只放拱心石**，避免和上方托架打架 |
| 每扇上層窗 | 一定有連續陽台、單窗陽台或窗前欄杆其中一種 |
| 內院立面 | 只放窗前欄杆，不放窗套、窗楣、牆面裝飾 |
| 百葉 | 每扇上層窗依機率決定：全開（收在側邊）、半開（一扇關上）、全關 |
| 牆面裝飾 | 沿用參考站規則（不放、全同、每層輪替、隨機），套用在 N 到 A 各列 |
| 簷口 | 街道和內院立面都有 |
| 孟莎屋頂 | 街道和內院立面都有。老虎窗對齊下方窗戶中線；街道立面用選定款式，內院用鋅板款；斜切轉角的斜面用圓窗款 |
| 屋脊花飾 | 開啟時，沿街道立面的陡坡頂放置；屋頂平台的角落放尖頂飾 |
| 煙囪 | 盲牆頂每 3–4 m 一座長條煙囪；屋頂平台沿中線每 2 個開間一座（2／4／6 個煙囪帽隨機），數量由密度控制 |

### 8.5 裝飾層級

| 層級 | 內容 |
|---|---|
| 0 | 不放窗套和窗楣 |
| 1 | 只放窗套 |
| 2（預設） | 依 8.4：N 最華麗，往上逐層簡化 |
| 3 | 豐富：S 列也輪流放弧形山花，牆面裝飾全開 |

山花樣式：
- **交替**：依開間奇偶，三角、弧形輪流。
- **中央強調**：中央開間放三角，其他放弧形。
- **全三角**、**全弧形**：所有開間都同一種。
- **平窗楣**：全部用兩端有托架的平窗楣。

### 8.6 隨機

每個隨機決定都用 `雜湊(種子, 立面, 開間, 樓層, 用途)` 產生，不依序抽亂數。這樣調整一個參數（例如上層數）時，其他位置的結果不會整個重新洗牌。參考站為了和 Blender 逐位相同而做的 float32 運算不需要移植。

### 8.7 輸出

```ts
interface Placement {
  key: string;                 // 例：COL[S_bay][1]
  matrix: Matrix4;             // Blender Z-up 空間
  tint?: Partial<Record<"stone" | "paint" | "fabric", Color>>;
  room?: RoomTag;              // 窗後有房間時（階段 F）
}
interface BuildingResult {
  placements: Placement[];
  roofCap: MeshData;           // 屋頂平台
  partyWalls: MeshData;        // 盲牆與防火山牆
  bounds: Box3;
}
```

- 之後做城市時，多棟建築的 placements 合併後再交給 `kit.ts`。同一個零件不論出現在幾棟建築，都只用一個 InstancedMesh，繪製次數不會隨建築數量增加。

```
  kit.ts（移植 v1）、generator.ts、params.ts、roof.ts、materials.ts、interiors.ts（階段 F）
```

- **流程**：`npm run kit` 依序執行 `build_kit.py` → `preview_kit.py` → `export_kit.py`；之後在 build 和 export 之間加上 `bake.py`。
- **`export_kit.py` 的修改**：
  - 改成自動匯出 `KIT` 集合底下的所有子集合，不再寫死港式清單。
  - 保留 UV0 和 UV1。
  - 不嵌入圖片（`export_image_format="NONE"`），貼圖另外放在 `tex/`。
  - manifest 額外記錄每個零件的三角形數。
- **哪些檔案進 git**：
  - `kit.glb`、manifest、`tex/`、`kit_preview.jpg` 要進 git。GitHub Actions 部署時不會跑 Blender。
  - `european_kit.blend` 不進 git（已列在 `.gitignore`），可以用腳本重建。
  - 室內圖集算圖很久，算好的 `interiors.jpg` 進 git。

## 10. 效能預算

| 項目 | 預算 |
|---|---|
| 一棟（預設參數） | ≤ 200,000 個三角形 |
| 繪製次數 | 每種「零件 × 材質」一次，與建築數量無關；全 kit 約 250 次以內 |
