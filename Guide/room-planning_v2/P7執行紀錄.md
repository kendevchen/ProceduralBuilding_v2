# P7 效能與現有功能整合執行紀錄

日期：2026-10-08。分支：`feature/room-editor`；前階段提交：`44fd149`。本輪完成快取、索引、家具與標籤共用及互動整合；大型效能門檻尚未通過，P7 不列為全數驗收完成。正式 GUI 仍為正面 10／側面 8／上層 6，尚未進入 P8。

## 1. 本輪變更

- `BuildingPipeline` 由每棟獨立持有結構、外觀配置資料、生成平面及編輯後平面。結構及平面 key 分開；窗扇角度、漆色、窗簾不重新規劃，老虎窗有無／形狀、一樓窗及門形會使平面失效。缺省與關閉的多樣性旗標同義。解析及重套成功後才替換快取，失敗保留上一個模型。
- 室內幾何以平面 key、編輯版號、相關家具參數及呈現模式判定是否可保留。換角度等外觀操作會保留室內、家具及同一平面的標籤；離開建築會釋放其室內，只留外殼與平面資料。
- 全域數值滑桿在拖動時以 120 ms 節流顯示外殼預覽；預覽不帶舊平面的窗後房盒、標籤或家具。放開後提交一次重建。個別窗角度／窗簾數值於提交時更新。房間／窗戶編輯及切棟先讓輸入事件結束，再執行重建；排程合併、棟 ID 檢查及切棟取消避免舊預覽重掛。
- 核心配置及編輯的房間到牆查詢、內襯的開口查詢建立索引。動線檢查依樓層縮小圖；同一房間起點到門的幾何路徑只計算一次，再套各樓梯距離。一次 checker 呼叫內，只有相同房間分類／住戶／核心 ID／多邊形／門節點及加權圖的樓層才共用水平稽核；實際門、平台、垂直樓梯／井檢查仍全數執行。
- 家具 recipe 共用原三角形、材質 stamp 及幾何，床、床頭櫃、檯燈、沙發、餐椅、餐具櫃及廚具採 `InstancedMesh`。鏡射預先烘入 recipe，實例矩陣保有正行列式。花紋的座標與法線包含實例變換，沒有刪家具或降低造型品質。
- 同字房名共用原 512×160 Canvas 貼圖；每間房仍有自己的 Sprite／材質、選取及展開變換。標示面積時按實際字串共用；貼圖由該組 `RoomLabels` 持有並釋放一次。
- 家具 SAT 與房內判定改用純量，減少短陣列配置；經證實為矩形的四邊輪廓可直接判定凸形包覆，凹形仍走原線段檢查。材質 stamp 直接寫入 typed array。

快取目前是棟級生成平面及整組室內幾何，尚未實作跨重建的逐層增量配置／逐層幾何快取。冷重建仍同步完成全棟；本輪沒有 Worker 或逐層背景補建，不以首屏時間代替整棟成本。

## 4. 尚未通過的項目

- 大型結構＋平面含硬檢查 p95 ≤100 ms，以及完整外觀＋平面＋室內＋家具 CPU p95 ≤300 ms，仍是未達成目標。
- GPU 首次編譯／上傳與純 GPU timer 未驗收。瀏覽器 renderer 提交 CPU 與兩次動畫幀等待分列，不能稱為 GPU 執行時間。
- 冷重建會阻塞主執行緒。需繼續處理規劃及幾何分項瓶頸，再考慮逐層快取、帶 generation token 的可見層優先排程及必要的資料 Worker；若採排程，應另列首屏與全棟完成時間。
- P8 正式 20 上限、配置模式 GUI 及最終規則文件尚未開始。本輪不推送，使用者原有文件搬移、刪除與設定變更保持原狀。

使用者於本輪後續選擇先進入 P8，開放 20 上限並保留上述效能限制；此為交付優先順序調整，不表示 100／300 ms 或 GPU 門檻已通過。
