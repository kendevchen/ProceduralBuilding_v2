# 20 上限平面配置規則

更新：2026-10-08。P8 已開放主介面；自動化回歸通過，新介面瀏覽器視覺驗收待連線恢復。大型效能目標尚未達成。原 [6層原平面配置規則.md](6層原平面配置規則.md) 保留為舊版基準；[20層平面建議.md](20層平面建議.md) 是原提案，現行行為以本文件、程式及 [P8 執行紀錄](P8執行紀錄.md) 為準。

## 1. 輸入、尺寸與層數

- 正面 `baysX`、側面 `baysY`：2–20 的整數；`floors`：1–20 的整數。限制唯一來源為 `blender/kit_dims.json` 的 `interior.planning.inputLimits`。
- `floors` 只算一樓與閣樓之間的上層；最大為一樓＋20 上層＋閣樓，共 22 層，名稱為 1F～21F、閣樓。奧斯曼樓高沿用 N／S／A 首中末層規則，均一配置全部為 S。
- 主介面新建輸入預設 `dimensionVersion="bays-v2"`、`layoutMode="auto"`。`defaultParams()` 舊 API 不改，未標版本的連棟仍精確使用 `depth` 公尺值。
- 新連棟由 `baysY × bay + 端柱餘量` 決定長度；相容公尺入口顯示 `depth` 並停用側面開間，不換算或四捨五入舊尺寸。例：舊 `12.345678 m` 原值保留；新連棟側面 16 開間實際長度為 49 m。
- 20 是輸入上限，不保證每個寬深／高度組合都能放下合法核心。2×2×20、2×20×20、20×2×20 等明確回報容量原因。

## 2. 模式選擇與不可行輸入

GUI 提供「自動／中庭／採光井」。自動模式仍在舊範圍（正面 ≤10、非連棟側面 ≤8／連棟實際進深 ≤20 m、上層 ≤6）時使用原結構；預設及舊最大場景的完整平面與舊版一致。

超出舊範圍後，淺平面試排多核心；深平面依 O 中庭、允許且可行的 U 中庭、採光井進行結構試排。明選中庭／採光井只驗證指定模式，不默默改選。原 API 明確 legacy 保留歷史入口；主介面的未標／legacy 輸入第一次修改即進入 auto，避免用舊演算法跳過大型可行性檢查。

拓撲成功還須生成完整平面並通過 checker。若房間輪廓、門窗歸屬、核心或公共路徑不合規則，主介面不替換舊模型，恢復最後有效滑桿／選單與尺寸，保留該棟房型編輯及復原歷史，顯示具體原因。路徑超過設定的 50 m（低層）／45 m（7 上層起）亦拒絕；不放寬門檻來讓矩陣通過。這是生成器的幾何規則，不代表真實建築法規認證。

512 組尺寸掃描觀測：211 組完整平面可生成，277 組在結構容量試排即拒絕，24 組因最終公共路徑超限拒絕。後者表示目前候選不能通過，不宣稱該基地在任何其他設計下都不可能；可以修改尺寸／層數或明確選另一模式重試。完整輸入與原因保存在 [P8上限檢查.json](P8上限檢查.json)。

## 3. 核心、公共動線與孔洞

共用不可變拓撲先保留格子、公共走廊、核心、孔洞與立面，再分配住戶。7–14 上層要求每戶可到兩座不同且連續至戶外的有效樓梯，並配置電梯；15–20 上層每核心雙梯／雙電梯。核心數量由實際寬深試排，不把整棟硬設為兩戶。

小型「每層戶數」與大型「每個核心戶數」均有自動／一戶／兩戶。強制選項仍受採光與最小房間容量限制，實際戶數及退回原因記於 `circulation.apartmentCounts`。樓梯、電梯廳、電梯、管道井與公共廊不能改為住宅或合併到住戶；設備門不作步行門。

樓梯的局部旋轉框架共用於梯段、平台及門口；井道、固定格界上下對齊。中庭、採光井、電梯與設備井對應真實樓板／天花／閣樓／屋頂孔洞，家具不進入孔洞。每個實際開口有唯一歸屬，設備井維護窗與住宅採光窗分開。

## 4. 採光井與中庭

採光井先枚舉組數、井列及房間帶並對齊開間格線；井列深度至少 `max(3 m, 0.1 × wallTop)`，向上對齊開間。高度增加時井深與可用組數一起重算，20 上層典型為 9 m 井列。預留公共連通與有效核心後才安排井與住宅，端欄到公共廊最多穿一間同戶房間。採光井有四面真實窗及通天洞，服務房型不全部假裝為住宅或儲藏間。

中庭先驗證 O／U 形的總寬深、翼寬、核心及淨庭尺寸，短邊至少 `max(6 m, 0.5 × wallTop)`。盲牆翼住宅朝庭，翼與轉角不得重疊。O 形一樓有頂門廊連接外側入口及庭院；U 形開口與凹角按共享屋頂區域處理。中庭與採光井首版不做宴會廳挑空，要求時記入診斷。

## 5. 樓層多樣性與戶型

「樓層配置多樣性」預設關閉；開啟後使用獨立、確定性隨機用途與最多八次重抽。合併與內部細分不能改核心、公共廊、孔洞或立面格界；重抽失敗保留合法重複／退回原因，不隱藏 checker 問題。

V1–V5 包含合法房型分配、接待／臥室合併及套房細分；分段模板 A／B／C 按容量解析，容量不足整段退回。深平面 D1–D3 與中庭 W1–W4 包含組模板、服務用途、井窗跨組與轉角跨翼合戶；跨組／跨翼住戶仍不佔公共路徑。詳細規則見根目錄 [INTERIOR_SPEC.md](../../INTERIOR_SPEC.md) 第 5 節。

P8 修正不同牆厚相鄰的房間輪廓：無論是否開多樣性，每個住宅牆段按實際牆厚內縮，避免較厚公共牆的內縮誤用到整條私用薄牆、讓門洞離開房間輪廓。

## 6. 互動、相機與棟級狀態

主介面數值拖曳保留節流外觀預覽，完成輸入才提交完整重建。棟級快取與個別編輯按棟隔離，切棟取消未提交工作；保存最後成功參數，不把未驗證候選尺寸存到其他棟。新增複製模式、尺寸版本與基本設定，使用新種子，清空個別門窗與房型編輯；新候選先通過平面檢查才加入棟群。

樓層滑桿跟隨實際層數；歸位相機、展開相機與環境陰影依包圍盒。固定展示視角放不下時，以視野與長寬比重新框住完整建築。自動展開切線避開所有樓梯、電梯廳與井道，找不到兩條安全切線時保留比例分段與手動剖切。

## 7. 效能及驗收限制

P7 桌機瀏覽器正式樣本（Apple M3 Pro，Chrome 154，5 暖機／30 樣本）的 20×20×20 整棟同步重建約 2.6–3.6 秒；預設約 221 ms。P8 保留面板說明與 [P7 執行紀錄](P7執行紀錄.md)，未將舊量測冒稱為 P8 新介面量測。

100 ms 結構／平面及 300 ms 整棟重建目標未全數通過；GPU 首次編譯／上傳、行動裝置與多棟 FPS 未量測。逐層增量／背景補建尚未實作。使用者明確選擇先開放 P8 並保留限制。

P8 自動化檢查涵蓋指定種子 1–10、512 組尺寸、96 個相機投影角點、舊 25,920 平面與 11 雜湊、核心／井／中庭／模板／房間／展開／多棟／透明度／家具快取及 build。瀏覽器目前無可用連線，本輪 GUI 操作與視覺驗收尚未完成，不能用 P7 截圖或舊互動結果代替。
